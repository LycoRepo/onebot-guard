# onebot-guard

> 状态：**初步可用，含运维 WebUI 的端点与路由编辑**。策略网关主体、事件与 Action 授权、限流去重、
> 请求关联、有界缓冲、故障语义、策略热重载、只读观测服务，以及带端点/路由可视化编辑（含增删）
> 与保存后重启的运维 WebUI、协议模拟端集成测试均已实现并通过门禁（`tsc --noEmit` 无错，
> 88 个用例 87 通过 / 1 个 Unix 信号用例在 Windows 跳过）。真实协议端兼容性与生产运行验证由部署方完成。

在 OneBot v11 协议实现端（QQ 侧）与机器人应用之间提供一层**可配置的策略网关**：
事件过滤与可见范围、Action 授权与资源范围、限流与去重、请求关联（`echo` 隔离）与运行观测。

## 定位

- **不绑定具体框架**：协议端可以是任意 OneBot v11 实现，下游可以是任意 OneBot v11 应用。
- **配置驱动**：谁能看到什么消息、谁能执行什么动作，全部写在配置里，可审计、可展开。
- **安全默认**：默认拒绝、拒绝优先于允许、未声明的能力默认关闭、凭据只从环境变量读取。
- **只绑回环**：默认只监听 `127.0.0.1`；跨机请走加密隧道或受限私有网络，不暴露裸 OneBot 端口。
- **有界**：缓冲、待回包请求、正则输入都有上限，慢下游不会把内存拖垮。

## 当前范围

包含：单条链路的真实可用性、配置校验与加载、事件授权、Action 授权（含参数与资源范围）、
`echo` 请求关联与隔离、去重与限流、有界缓冲、故障语义、策略热重载、日志与 `/health`、`/stats`，
独立端口的运维 WebUI（状态面板、SSE 元数据日志、策略编辑、端点与路由的编辑/增删/保存后重启），
以及随批交付的单元测试与协议模拟端集成测试。

暂不包含：`runtime`／`observability`／TLS 等运行参数的面板编辑、配置历史与回滚、用户体系与
多账号权限、历史指标持久化、主动会话调度、嵌入式 SDK、多副本部署、兼容性矩阵、完整示例库。

## 运维 WebUI

默认关闭；开启后默认在回环地址的 3012 端口监听，未认证只返回独立登录页。六个页面：
概览、连接端点、消息路由、过滤规则、实时日志、策略 YAML。浅色控制台适配桌面与窄屏；
概览先显示「上游 → 策略 → 下游」的实际就绪状态，并按「连接端点 → 关联路由 → 设置规则」引导配置。

- **端点页**：上游、下游各自分组，每个端点一张整宽卡片；字段一行一个（左侧中文标签 +
  英文配置键，右侧控件、说明与错误）。可以**新增端点**（先连接与身份、再路由关联，可顺带
  新建一条路由，也可「仅加入草稿，稍后关联」）和**删除端点**（列出引用它的路由与另一侧端点，
  可一并删除这些路由，或取消删除）。
- **路由页**：增删路由，从端点与策略名称中选择上游、下游和策略；同时保留当前实例的路由运行状态。
- **共享草稿**：端点页与路由页共用一份草稿和顶部常驻操作条，显示未保存摘要；三秒状态轮询
  不覆盖草稿；可撤销到最近保存版本。规则与 YAML 也有撤销和离开提醒。运行读数（`/api/state`）读的是运行实例，与已保存但尚未生效的配置可能不同。
- **保存 ≠ 生效**：保存只落盘（200）；端点与路由改动**不热重载**，必须重启进程，「保存并重启」
  返回 202，由容器 `restart: unless-stopped` 拉起新实例。策略改动走热重载。刷新后仍能识别待重启配置；
  存在待生效的非策略改动时，面板提示先重启，并暂停规则/YAML 保存。
- **规则与日志**：可选择要编辑的策略，规则与完整 YAML 保存后同步；日志支持类型筛选和文本搜索，仍受环形缓冲容量限制。
- **服务端校验是唯一权威**：保存前对整份配置跑 `validateConfig`，被拒绝时文件字节不动 ——
  至少保留一条路由、每个下游只能绑定一条路由、全部端点必须被路由引用、端点 ID 全局唯一且不超过
  64 字符。端点数上限由 `runtime.max_connections` 决定（默认 64，不得小于端点数），该值不在面板
  编辑范围。

## 开发

```bash
npm ci                  # 安装依赖（Node >= 24）
cp config/gateway.example.yaml config/gateway.yaml   # 真实配置，已被 .gitignore 忽略
npm run typecheck       # tsc --noEmit
npm test                # node --test
docker compose up -d --build
```

Node 24 原生执行 TypeScript（类型剥离），因此运行不需要构建产物；**类型检查是独立门禁**，
必须在 CI 与本地都通过。面板前端是浏览器原生 HTML/CSS/JS，手写、无框架、无打包器、无构建步骤；
`src/webui/static/` 下的资源按请求读取并一律 `Cache-Control: no-store`，改完刷新页面即可看到。
